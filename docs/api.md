# HTTP API и веб-интерфейс

По умолчанию интерфейс доступен на `http://127.0.0.1:8765/`. UI и API обслуживаются тем же HTTP-процессом, который принимает камеры. Все маршруты локальные и не требуют сторонних Python-библиотек.

## Маршруты

| Метод | Путь | Успешный ответ |
|---|---|---|
| `GET`, `HEAD` | `/` | HTML веб-интерфейса |
| `GET`, `HEAD` | `/static/styles.css`, `/static/app.js`, `/static/favicon.svg` | Статические файлы из фиксированного списка |
| `GET`, `HEAD` | `/api/health` | JSON-состояние HTTP-сервера и архива |
| `GET` | `/api/videos` | JSON-массив завершённых записей |
| `GET`, `HEAD` | `/api/videos/{name}` | MP4 целиком или запрошенный диапазон байтов |

Неизвестные маршруты возвращают `404`. Произвольные пути через static-маршрут недоступны: сервер отдаёт только перечисленные выше ресурсы.

## Проверка состояния

`GET /api/health` подтверждает доступность HTTP API и сообщает состояние обработчика архива:

```json
{
  "status": "ok",
  "archive": {
    "state": "running",
    "source": "ffmpeg",
    "last_error": null,
    "cameras": [
      {"id": "entrance", "state": "running", "last_error": null},
      {"id": "yard", "state": "degraded", "last_error": "SourceError: FFmpeg завершился (код 1)"}
    ]
  }
}
```

Состояния: `running` — фоновый приёмник работает; `degraded` — была ошибка, идёт или ожидается повторное подключение; `stopped` — поток архива остановлен; `disabled` — источник не задан. Для нескольких камер `archive.state` — общее состояние, а `archive.cameras` даёт состояние каждой камеры отдельно. При `VIDEO_SOURCE=none` поле `cameras` пустое. В одиночном режиме оно содержит ноль или один элемент.

`last_error` равен `null`, если у источника нет текущей ошибки. В сетевом режиме значение `source` — `ffmpeg`; в одиночном режиме оно также может быть `synthetic`, `inbox` или `none`.

## Список записей

`GET /api/videos` возвращает записи из корня `VIDEO_RECORDINGS_DIR`, отсортированные по `started_at` от новых к старым. Вложенные папки не обходятся. Незавершённые файлы и файлы с неподходящими именами игнорируются.

```json
{
  "videos": [
    {
      "name": "2026-10-15_09-00-00__entrance.mp4",
      "started_at": "2026-10-15T09:00:00",
      "size_bytes": 84000000,
      "duration_seconds": 3600.0,
      "camera_id": "entrance"
    }
  ]
}
```

- `name` — архивное имя MP4.
- `started_at` — локальное время начала, ISO-формат без часового смещения.
- `size_bytes` — размер файла в байтах.
- `duration_seconds` — число секунд по `ffprobe` или `null`, если утилита отсутствует, не смогла прочитать файл или превысила таймаут.
- `camera_id` — идентификатор после `__` в имени либо `null`.

Если каталог архива не читается, маршрут отвечает `500` с JSON-полями `error` и `detail`.

## Получение видео и перемотка

`GET /api/videos/{name}` принимает только допустимое архивное имя. Он разрешает файл через `VideoStorage.path_for`, проверяя, что имя соответствует формату, путь существует, является файлом и остаётся непосредственно в корне архива.

Поддерживается один заголовок Range за запрос:

```http
Range: bytes=0-1023
```

Также поддерживаются открытая правая граница (`bytes=1024-`) и суффикс (`bytes=-1024`). Ответ на корректный Range имеет `206 Partial Content`, `Accept-Ranges: bytes`, `Content-Range` и `Content-Length`. Без Range возвращается `200 OK` и весь файл. Множественные диапазоны не поддерживаются.

Коды ошибок видео-маршрута:

- `400` — имя не соответствует разрешённому формату.
- `404` — запись с корректным именем отсутствует.
- `416` — диапазон байтов некорректен или выходит за размер файла; ответ включает `Content-Range: bytes */<размер>`.

При разрыве соединения клиентом сервер прекращает передачу и пишет диагностическое сообщение уровня DEBUG.

## Веб-интерфейс

Файлы страницы находятся в `static/`. Сборщик, серверный шаблонизатор и внешние JavaScript-библиотеки не используются.

- При загрузке страница параллельно запрашивает `/api/health` и `/api/videos`.
- Список создаётся из API-данных через DOM-элементы и `textContent`; имена файлов не вставляются как HTML.
- Группы формируются по `camera_id` из имени записи. Если ID отсутствует, запись попадает в группу «Источник без идентификатора».
- Поиск проверяет имя файла без учёта регистра; фильтр даты сверяет локальную дату в `started_at`. Фильтры выполняются на уже загруженном списке.
- Список и статус обновляются вручную кнопкой или автоматически каждые 30 секунд. Таймер приостанавливается, когда вкладка скрыта.
- При обновлении сохраняются введённые фильтры и выбранный плеер. Плеер загружает видео напрямую по `/api/videos/{name}`, с `preload="metadata"` и поддержкой Range со стороны сервера.
- Ошибка соединения, пустой архив и ошибка декодирования имеют отдельные состояния в интерфейсе.

Для статических ответов выставляются `Cache-Control: no-cache`, `X-Content-Type-Options: nosniff` и Content Security Policy, разрешающая скрипты, стили и медиаданные только с этого же источника. JSON API выдаёт `Cache-Control: no-store`.

## Примеры запросов

```powershell
curl http://127.0.0.1:8765/api/health
curl http://127.0.0.1:8765/api/videos
curl -H "Range: bytes=0-1023" http://127.0.0.1:8765/api/videos/2026-10-15_09-00-00.mp4 --output chunk.bin
```
