# Настройка

Все настройки читаются из переменных среды при старте `main.py`. Файл `.env` автоматически не загружается. Изменение параметров не применяется к уже работающему процессу: остановите и запустите сервис снова.

## Переменные среды

| Переменная | Значение по умолчанию | Описание и проверки |
|---|---:|---|
| `VIDEO_HOST` | `127.0.0.1` | Адрес HTTP-сервера. `127.0.0.1` ограничивает доступ этим компьютером; `0.0.0.0` слушает все сетевые интерфейсы. |
| `VIDEO_PORT` | `8765` | Порт веб-сервера, диапазон `1..65535`. |
| `VIDEO_RECORDINGS_DIR` | `recordings` | Каталог готовых записей. |
| `VIDEO_TEMP_DIR` | `temp` | Корневой каталог временных сегментов; в многокамерном режиме внутри него создаются подпапки по ID камеры. |
| `VIDEO_INBOX_DIR` | `inbox` | Каталог готовых файлов для `VIDEO_SOURCE=inbox`. |
| `VIDEO_SEGMENT_SECONDS` | `3600` | Длительность сегмента. Должна быть больше нуля; значение 3600 выравнивается по локальному часу. |
| `VIDEO_SOURCE` | `none` | Режим одиночного источника: `none`, `synthetic`, `ffmpeg` или `inbox`. |
| `VIDEO_SOURCE_URL` | — | URL RTSP, HTTP или HTTPS для `VIDEO_SOURCE=ffmpeg`; обязателен в этом режиме. |
| `VIDEO_CAMERA_ID` | — | Необязательный ID одиночной камеры; добавляется к имени файла после `__`. |
| `VIDEO_CAMERAS` | — | JSON-массив сетевых камер для одновременной записи в одном процессе. Взаимоисключает настройки одиночного источника. |
| `VIDEO_FFMPEG` | `ffmpeg` | Имя или полный путь к исполняемому файлу FFmpeg. |
| `VIDEO_FFPROBE` | `ffprobe` | Имя или полный путь к `ffprobe`; используется для получения длительности. |
| `VIDEO_SOURCE_TIMEOUT_SECONDS` | `15` | Таймаут ожидания сетевых данных; должен быть больше нуля. |
| `VIDEO_RETRY_SECONDS` | `5` | Пауза перед повтором после сбоя; не может быть отрицательной. |
| `VIDEO_INBOX_STABILITY_SECONDS` | `3` | Сколько секунд размер и время изменения входного MP4 должны быть неизменны перед импортом; не может быть отрицательным. Маркер `.ready` позволяет не ждать. |
| `VIDEO_MIN_FREE_BYTES` | `268435456` | Минимум свободного места, которое должно остаться после публикации сегмента; `0` отключает резервный порог. |
| `VIDEO_LOG_LEVEL` | `INFO` | Уровень стандартного Python logging, например `DEBUG`, `INFO`, `WARNING` или `ERROR`. |

Относительные пути разрешаются от текущей рабочей папки, из которой запущен `python main.py`, а не от папки каждого видеофайла. Папки `recordings/` и `temp/` создаются при старте. `inbox/` создаётся при работе приёмника этого режима.

## Одна камера

Одиночный режим сохраняет совместимость с переменными `VIDEO_SOURCE`, `VIDEO_SOURCE_URL` и `VIDEO_CAMERA_ID`:

```powershell
$env:VIDEO_SOURCE = "ffmpeg"
$env:VIDEO_SOURCE_URL = "rtsp://USER:PASSWORD@192.168.1.20:554/stream1"
$env:VIDEO_CAMERA_ID = "entrance"
python main.py
```

На Linux используйте переменные среды оболочки:

```sh
export VIDEO_SOURCE=ffmpeg
export VIDEO_SOURCE_URL='rtsp://USER:PASSWORD@192.168.1.20:554/stream1'
export VIDEO_CAMERA_ID=entrance
python3 main.py
```

Получите точный URL из документации или настроек камеры. Путь потока и порт зависят от модели. Не помещайте рабочие пароли и реальные адреса в файлы, которые будут отправлены в репозиторий. Символы URL, зарезервированные протоколом, могут требовать percent-encoding в логине или пароле.

Если `VIDEO_CAMERA_ID` не задан, файл получает имя без суффикса камеры и в интерфейсе попадает в группу «Источник без идентификатора».

## Несколько камер в одном процессе

Укажите массив объектов с обязательными строковыми полями `id` и `url`:

```powershell
$env:VIDEO_CAMERAS = '[{"id":"entrance","url":"rtsp://USER:PASSWORD@192.168.1.20:554/stream1"},{"id":"yard","url":"rtsp://USER:PASSWORD@192.168.1.21:554/stream1"}]'
python main.py
```

На Linux тот же JSON задаётся в переменной среды:

```sh
export VIDEO_CAMERAS='[{"id":"entrance","url":"rtsp://USER:PASSWORD@192.168.1.20:554/stream1"},{"id":"yard","url":"rtsp://USER:PASSWORD@192.168.1.21:554/stream1"}]'
python3 main.py
```

Каждому объекту нужны уникальный `id` и непустой `url`, начинающийся с `rtsp://`, `http://` или `https://`. ID должен соответствовать шаблону `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`, не оканчиваться точкой и не быть зарезервированным именем Windows (`CON`, `NUL`, `COM1` и т. п.). ID в массиве должны быть уникальными без учёта регистра: Windows не различает регистр в именах каталогов, Linux — различает. Адреса проверяются по форме, но их доступность и правильность учётных данных проверяются только при соединении с камерой.

Камеры записываются параллельно, каждая в собственном потоке и в собственной временной папке `temp/<id>/`; готовые видео лежат вместе в `recordings/`. На каждой записи появляется `__<id>`, поэтому веб-интерфейс группирует архив по источникам. Все камеры используют общие `VIDEO_SEGMENT_SECONDS`, таймауты, каталог архива и порт веб-сервера.

Не задавайте одновременно `VIDEO_CAMERAS` и `VIDEO_SOURCE_URL`/`VIDEO_CAMERA_ID` или активный `VIDEO_SOURCE` (`synthetic`, `ffmpeg`, `inbox`). Для одной камеры можно использовать как одиночные переменные, так и массив `VIDEO_CAMERAS` из одного объекта.

## Тестовый видеопоток

`synthetic` создаёт локальное видео и звук без камеры:

```powershell
$env:VIDEO_SOURCE = "synthetic"
$env:VIDEO_SEGMENT_SECONDS = "10"
python main.py
```

Эквивалентный запуск на Linux:

```sh
export VIDEO_SOURCE=synthetic
export VIDEO_SEGMENT_SECONDS=10
python3 main.py
```

Сборка FFmpeg должна содержать `libx264` и AAC. Удалите или сбросьте `VIDEO_SEGMENT_SECONDS`, чтобы вернуться к одному часу.

## Прямой просмотр в браузере

После настройки `VIDEO_SOURCE=ffmpeg` или `VIDEO_CAMERAS` откройте главную страницу и в разделе «Камеры онлайн» выберите источник и нажмите «Открыть эфир». Для нескольких камер список содержит отдельный пункт на каждую камеру. Просмотр передаёт изображение в браузер как MJPEG и не создаёт архивный файл; обычная запись при этом продолжается.

Для проверки интерфейса без физической камеры запустите `VIDEO_SOURCE=synthetic` и откройте ту же страницу. В браузере появится тестовая цветная видеокартинка. Режим `inbox` принимает только уже готовые MP4-файлы, поэтому живого источника для просмотра в нём нет.

Каждый открытый просмотр создаёт отдельный FFmpeg-процесс и отдельное соединение с камерой. Одновременно разрешено не более четырёх просмотров. Если камера ограничивает число подключений, просмотр может не открыться во время активной записи.

## Импорт готовых MP4

Для готовых файлов включите одиночный режим `inbox`:

```powershell
$env:VIDEO_SOURCE = "inbox"
python main.py
```

На Linux:

```sh
export VIDEO_SOURCE=inbox
python3 main.py
```

Помещайте полностью закрытые MP4 в `inbox/`, например `2026-10-15_09-00-00__entrance.mp4`. Поддерживаются имена `YYYY-MM-DD_HH-MM-SS.mp4` и `YYYY-MM-DD_HH-MM-SS__camera-id.mp4`. Рядом можно создать пустой маркер `имя.mp4.ready`: он сообщает приёмнику, что копирование завершено. После успешного импорта сервис переносит содержимое в `recordings/`, затем удаляет исходный файл и маркер. Файл не перекодируется и не делится на сегменты.
