# Настольное приложение

## Что входит в приложение

Окно содержит три раздела:

- **Прямой эфир** — выбор источника и просмотр видео с камеры или тестового потока.
- **Архив записей** — список готовых MP4, поиск и встроенное воспроизведение.
- **Источники и настройки** — добавление, изменение и удаление камер, выбор режима, длина сегмента и каталоги хранения.

Кнопка в заголовке окна запускает или останавливает запись. Изменение настроек во время записи требует подтверждения, поскольку текущий сегмент будет закрыт и конфигурация применится заново. Интерфейс работает с API локального сервера, который запускается внутри процесса приложения; браузер не открывается.

По умолчанию приложение не начинает запись само. Добавьте камеры или выберите другой режим, нажмите **Сохранить и применить**, затем **Начать запись**. Для прямого просмотра выберите источник на вкладке **Прямой эфир**.

### Нужны ли файлы Python

Для запуска готового `VideoArchive.exe` в Windows или `VideoArchive` в Linux файлы `.py` не нужны: сборка `--onefile` уже содержит CPython, используемые модули приложения, PySide6 и каталог `static/`. Системные графические библиотеки Linux остаются зависимостью ОС. FFmpeg, настройки, журнал и архив видео хранятся отдельно в пользовательском каталоге данных.

Исходники `.py`, файлы зависимостей и скрипты сборки нужно сохранить, если вы хотите менять программу, собирать её заново или запускать сервер командой `python main.py`. Для обычного запуска можно скопировать только исполняемый файл нужной ОС.

## FFmpeg при первом запуске

Приложение сначала ищет одновременно `ffmpeg` и `ffprobe` в `PATH`. Если одного из них нет, автоматически загружает и устанавливает оба файла в пользовательский каталог приложения. Архив проверяется по SHA-256 до распаковки, затем обе программы проверяются запуском с `-version`. Для первой установки требуется подключение к интернету. При наличии обеих программ в `PATH` загрузка не нужна.

После установки приложение использует сохранённые копии FFmpeg при следующих запусках, повторно скачивать их не нужно. Пользователю не требуется отдельно устанавливать Python или Qt.

- Windows: архив FFmpeg Essentials с Gyan.dev.
- Linux x86-64 и ARM64: статическая сборка FFmpeg из релиза BtbN/FFmpeg-Builds.

Лицензионные условия FFmpeg и выбранной сборки распространяются на загружаемые программы; приложение не включает FFmpeg в свой исполняемый файл.

## Сборки

### Запустить приложение

В Windows дважды щёлкните `VideoArchive.exe` — локально собранный файл находится в `output/windows/VideoArchive.exe`. Это один исполняемый файл; он открывает собственное окно приложения и не запускает браузер. Если FFmpeg не установлен, при первом запуске потребуется интернет для его загрузки. После этого приложение можно запускать обычным способом.

В Linux запустите файл `VideoArchive` из скачанной сборки. При необходимости сначала выполните `chmod +x VideoArchive`.

### Совместимость Linux

Официальная сборка создаётся для Linux x86-64 в контейнере с glibc 2.28 и использует PySide6 6.9.3. Практический минимальный порог для этой сборки — glibc 2.28; проверьте архитектуру и версию командой:

```sh
uname -m
getconf GNU_LIBC_VERSION
```

Поддерживается 64-битный `x86_64` с glibc 2.28 или новее и установленными системными библиотеками графического стола. Это включает многие распространённые дистрибутивы, но не гарантирует запуск буквально на каждом Linux: Alpine/musl, 32-битные системы и Linux ARM64 этой сборкой не покрываются. PyInstaller не включает glibc в приложение, поэтому сборка намеренно делается на старой базовой версии; новая glibc обычно совместима со старой сборкой, обратное не гарантируется.

### Скачать готовую сборку

Workflow **Desktop builds** создаёт артефакты `VideoArchive-Windows` и `VideoArchive-Linux` после отправки коммита в ветку `main`. Откройте раздел **Actions**, выберите успешный запуск **Desktop builds** и скачайте нужный артефакт. Эти артефакты хранятся GitHub ограниченное время согласно настройкам репозитория; это не постоянная страница релиза.

Windows-файл: `VideoArchive.exe`. Linux-файл: `VideoArchive`; сделайте его исполняемым при необходимости командой `chmod +x VideoArchive`.

### Собрать локально

Для сборки нужен Python 3.10 или новее и доступ в интернет для загрузки Python-зависимостей.

Windows PowerShell, из корня проекта:

```powershell
./build_desktop.ps1
```

Результат: `output/windows/VideoArchive.exe`.

Linux:

```sh
sh ./build_desktop.sh
```

Результат: `output/linux/VideoArchive`. Локальная сборка использует системную версию glibc и подходит для машины сборки. Для переносимого Linux-файла используйте Docker-сборку с базовым контейнером glibc 2.28:

```sh
docker build -f docker/linux/Dockerfile -t videoarchive-linux-builder:glibc228 docker/linux
docker run --rm -v "$PWD:/io" -w /io \
  -e VIDEOARCHIVE_BUILD_PYTHON=/opt/cpython/bin/python3.12 \
  -e VIDEOARCHIVE_BUILD_VENV=/tmp/videoarchive-venv \
  videoarchive-linux-builder:glibc228 sh ./build_desktop.sh
```

Результат будет в `output/linux/VideoArchive`; тот же контейнер используется GitHub Actions.

Windows-сборку нужно создавать на Windows, а Linux-сборку — на Linux. GitHub Actions запускает отдельную сборку на каждой системе. Запуск бинарного файла на других вариантах Linux может зависеть от версии системных библиотек и архитектуры процессора.

## Файлы пользователя

Настройки и автоматически установленный FFmpeg находятся вне каталога программы:

- Windows: `%LOCALAPPDATA%\VideoArchiveService\`
- Linux: `$XDG_DATA_HOME/VideoArchiveService/`, либо `~/.local/share/VideoArchiveService/`, если `XDG_DATA_HOME` не задан.

В этом каталоге приложение хранит `settings.json`, журнал `desktop.log`, папки архива и временных файлов, а также `tools/ffmpeg/`. По умолчанию все папки видео хранятся там же. Можно выбрать другие каталоги в приложении.

В `settings.json` URL камер сохраняются вместе с учётными данными, если они указаны в URL. Файл не зашифрован; ограничьте доступ к своей учётной записи ОС и не публикуйте его.

## Ограничения

- Настольное приложение и его сборка рассчитаны на Windows и Linux; официальный Linux-артефакт предназначен для x86-64 с glibc 2.28+.
- Автоматическая загрузка FFmpeg поддерживает Linux x86-64 и ARM64, но это не означает, что текущий Linux-файл приложения собран для ARM64.
- Настоящая камера для сборки не нужна, однако реальную совместимость live-просмотра и записи можно подтвердить только с доступным URL камеры.
- Воспроизведение зависит от поддержки кодека мультимедийным backend Qt на компьютере.
- При отсутствии системного FFmpeg первичная настройка требует интернета.
