# Эксплуатация и устранение ошибок

## Требования

- Python 3.8 или новее.
- FFmpeg для источников `ffmpeg` и `synthetic`.
- `ffprobe` необязателен; без него видео всё равно доступны, но API возвращает `duration_seconds: null`.
- Проект использует только стандартную библиотеку Python. `requirements.txt` не устанавливает дополнительных пакетов.

Проверьте доступность утилит:

```powershell
python --version
ffmpeg -version
ffprobe -version
```

Если `ffmpeg` или `ffprobe` не находятся через `PATH`, задайте `VIDEO_FFMPEG` и/или `VIDEO_FFPROBE` полными путями к файлам.

## Установка и запуск на Windows

Из корня проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
ffmpeg -version
.\.venv\Scripts\python.exe main.py
```

Откройте `http://127.0.0.1:8765/`. Для записи настройте источник до запуска по инструкциям в [настройке](configuration.md). Переменные среды относятся к тому процессу PowerShell, из которого запускается Python.

## Установка и запуск на Linux/macOS

Установите Python и FFmpeg средствами своей ОС, затем из корня проекта:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
ffmpeg -version
python main.py
```

В браузере откройте `http://127.0.0.1:8765/`.

## Остановка и перезапуск

Нажмите `Ctrl+C` в терминале, где запущен `main.py`. При штатном завершении приложение закрывает HTTP-сервер и передаёт каждому FFmpeg команду для закрытия сегмента. Если параметры среды меняются, остановите сервер и запустите новый процесс. При потере источника сервис повторяет подключение автоматически; перезапускать приложение для обычного сетевого обрыва не требуется.

## Проверка состояния

Откройте `http://127.0.0.1:8765/api/health` или выполните:

```powershell
curl http://127.0.0.1:8765/api/health
```

Поле `status: ok` означает, что HTTP API отвечает. `archive.state` показывает состояние фоновой записи; для нескольких камер смотрите отдельные значения в `archive.cameras`. `last_error` содержит последнюю ошибку приёмника и очищается после старта/успешной работы источника.

Пример:

```json
{
  "status": "ok",
  "archive": {
    "state": "degraded",
    "source": "ffmpeg",
    "last_error": "yard: SourceError: FFmpeg завершился (код 1)",
    "cameras": [
      {"id": "entrance", "state": "running", "last_error": null},
      {"id": "yard", "state": "degraded", "last_error": "SourceError: FFmpeg завершился (код 1)"}
    ]
  }
}
```

Приёмник FFmpeg не публикует диагностический вывод дочернего процесса в терминал: stdout и stderr FFmpeg направляются в `DEVNULL`. Журнал приложения сообщает, что источник запущен, повторно подключается, завершился с кодом или не может быть запущен. Проверяйте адрес, сеть и совместимость потока отдельно, если подробная диагностика FFmpeg нужна.

## Каталоги данных

| Каталог | Содержимое | Рекомендация |
|---|---|---|
| `recordings/` | Завершённые MP4, доступные через API и UI | Основные архивные данные; резервируйте этот каталог. |
| `temp/` | Открытые сегменты, списки сегментов FFmpeg; в multi-camera режиме — подпапки камер | Не используйте как готовый архив. Незавершённые сегменты после аварии могут быть удалены. |
| `inbox/` | Готовые файлы, ожидающие импорта в режиме `inbox` | Удаление исходника происходит после успешной публикации в `recordings/`. |

Каталоги относительно текущей папки запуска, если настройки не заданы абсолютными путями. Удаление или очистка `recordings/` не выполняется самим приложением. Встроенной политики срока хранения, квот, архивации или удаления старых записей нет.

## Резервное копирование и свободное место

Резервируйте завершённые файлы из `recordings/`. Для согласованной копии, исключающей текущий staging-файл, остановите сервис на время резервного копирования или используйте механизм снимков файловой системы. Не считайте `temp/` резервной копией: он содержит текущую запись и служебные файлы.

Перед публикацией каждого сегмента проверяется свободное место. После предполагаемой записи должно остаться не меньше `VIDEO_MIN_FREE_BYTES` (по умолчанию 256 MiB). Если порог не соблюдается, сегмент не публикуется, ошибка появляется в статусе, а сетевой приёмник запускает цикл повторного подключения. Освободите место; сервис сам старые записи не удаляет.

## Доступ по локальной сети

По умолчанию HTTP-сервер доступен только с этого компьютера на `127.0.0.1:8765`. Для доступа по LAN задайте, например, `VIDEO_HOST=0.0.0.0` и разрешите нужный порт в брандмауэре. После этого проверьте соединение с доверенного устройства.

В текущем приложении нет аутентификации, авторизации, TLS и защиты учётных данных в URL камеры. Не публикуйте порт напрямую в Интернет и не коммитьте реальные RTSP-адреса, логины или пароли в репозиторий. Приватность GitHub-репозитория сама по себе не защищает запущенный веб-сервис.

## Частые ошибки

| Симптом | Что проверить |
|---|---|
| `Не удалось запустить FFmpeg` | Установлен ли FFmpeg; доступен ли он в `PATH`; корректно ли задан `VIDEO_FFMPEG`. |
| `VIDEO_SOURCE=ffmpeg` без URL | Задать `VIDEO_SOURCE_URL` для одиночного режима. |
| Ошибка `VIDEO_CAMERAS` | Передать непустой корректный JSON-массив; у каждого элемента должны быть уникальный допустимый `id` и URL со схемой `rtsp://`, `http://` или `https://`. Не смешивать его с настройками одиночного источника. |
| Камера переподключается | Проверить точность URL и пути, порт, DNS/IP, доступность камеры, учётные данные, сетевой маршрут, кодек и `VIDEO_SOURCE_TIMEOUT_SECONDS`. |
| Порт уже используется | Изменить `VIDEO_PORT` или остановить другой процесс, слушающий этот порт. |
| Файлы не появляются в архиве | Проверить `/api/health`, источник и его статус, свободное место, `VIDEO_RECORDINGS_DIR`, а для `inbox` — формат имени, завершённость файла и наличие `.ready` либо истечение периода стабильности. |
| Ошибка «Запись уже существует» | Архив не перезаписывает файлы. Использовать уникальные ID камер и проверить повторяющиеся локальные времена/имена; существующий файл удалить вручную только если он действительно больше не нужен. |
| Видео не проигрывается в браузере | Проверить, что файл завершённый и доступен через API. Кодек может поддерживаться FFmpeg, но не браузером; сервер копирует поток без перекодирования. |
| `duration_seconds` равен `null` | Установить `ffprobe`, добавить его в `PATH` или задать `VIDEO_FFPROBE`; проверить, что файл корректный MP4. |

## Известные эксплуатационные ограничения

- Аутентификация, управление источниками из браузера, удаление записей через UI/API и автоматическая очистка старых файлов не реализованы.
- Многокамерный режим запускает отдельный процесс FFmpeg на каждую сетевую камеру; верхнее число камер проектом не ограничено, но практически зависит от сети, CPU, кодеков и дисковой подсистемы.
- Перекодирования нет: данные сохраняются с кодеками камеры. Плеер браузера может не поддерживать такие кодеки.
- Сегмент закрывается на подходящем ключевом кадре; фактическая граница иногда отличается от точного интервала.
- Локальное имя файла использует местное время без временной зоны. Повтор часа при осеннем переходе может привести к конфликту имён; замена файла запрещена.
