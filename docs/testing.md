# Проверки

В проекте используются стандартные `unittest` и временные каталоги. Для запуска из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

Если используется виртуальное окружение, Windows-команда:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На Linux из активированного виртуального окружения используйте:

```sh
python3 -m unittest discover -s tests -v
```

Либо без активации окружения:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты не подключаются к настоящим камерам. Большинство проверок не требуют FFmpeg; тест `test_live_sources_and_mjpeg_stream` запускает FFmpeg с синтетическим видеорядом и проверяет, что HTTP-маршрут выдаёт MJPEG-кадры. Если FFmpeg отсутствует, этот тест пропускается.

## Покрытие по файлам

- `tests/test_receiver.py`: параметры сегментного FFmpeg muxer, сетевой timeout, приём файла по `.ready` и пропуск MP4 с неподходящим именем.
- `tests/test_archive.py`: вычисление часовой/настраиваемой границы, публикация с ID камеры и повторное подключение после имитированного исключения.
- `tests/test_storage.py`: создание папок, формат имён, запрет перезаписи, отказ от пустого сегмента, сортировка архива, проверка traversal-пути и импорт готового файла.
- `tests/test_video_routes.py`: список и health API, synthetic live-источники и MJPEG-поток, HTML и статические файлы, Range-заголовки и соответствующие статусы, недопустимые и отсутствующие видео.

## Границы проверок

Автоматические проверки не подтверждают совместимость с конкретной моделью камеры, реальным RTSP/HTTP-адресом, сетевыми условиями, кодеком браузера или длительной многокамерной нагрузкой. Для приёмочного испытания нужно отдельно подключить камеру, проверить live-картинку в браузере, `/api/health`, появление завершённого файла в `recordings/` и воспроизведение записи.

Тестовая синтетическая камера запускается отдельно через `VIDEO_SOURCE=synthetic`; ей необходим FFmpeg с `libx264` и AAC.
