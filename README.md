# Сервис видеоархива

Сервис принимает видеопоток, сохраняет завершённые MP4-сегменты и предоставляет веб-интерфейс для поиска и просмотра записей. HTML-страница и API работают на одном Python HTTP-сервере.

## Быстрый старт

Требуются Python 3.8+ и FFmpeg в `PATH` для сетевых или синтетических источников. Python-пакеты из сторонних источников сервису не нужны.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
ffmpeg -version
.\.venv\Scripts\python.exe main.py
```

Откройте `http://127.0.0.1:8765/`. Без настройки `VIDEO_SOURCE` или `VIDEO_CAMERAS` запускается только HTTP-интерфейс, запись не ведётся. Полные инструкции по источникам приведены в [настройке](docs/configuration.md).

## Архитектура

- `main.py` — HTTP-сервер и маршруты API.
- `static/index.html`, `static/styles.css`, `static/app.js` — браузерный интерфейс без сборщика и frontend-зависимостей.
- `archive.py` — фоновый запуск одного или нескольких источников, обработка ошибок и публикация готовых сегментов.
- `receiver.py` — FFmpeg-источник, тестовый источник и наблюдатель за папкой готовых файлов.
- `storage.py` — безопасные имена, публикация без перезаписи и поиск записей.
- `config.py` — конфигурация через переменные среды.
- `tests/` — автоматические проверки без настоящей камеры.

Для RTSP/HTTP FFmpeg держит входное соединение и использует сегментный muxer с привязкой к локальным часам. Для готовых файлов включается режим `inbox`: файл импортируется без перекодирования и повторного разделения.

## Требования и установка

- Python 3.8 или новее.
- Для источников `synthetic` и `ffmpeg` требуется FFmpeg. Для длительности видео в списке API дополнительно используется `ffprobe`; без него поле `duration_seconds` будет `null`.
- В Python-зависимостях используется только стандартная библиотека.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

На Linux активируйте окружение командой `source .venv/bin/activate`. FFmpeg нужно установить отдельно и добавить `ffmpeg` (и при необходимости `ffprobe`) в `PATH`, либо задать `VIDEO_FFMPEG` и `VIDEO_FFPROBE`.

## Настройка

Все переменные необязательны, если не указано иное.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VIDEO_HOST` | `127.0.0.1` | Адрес HTTP-сервера |
| `VIDEO_PORT` | `8765` | Порт |
| `VIDEO_RECORDINGS_DIR` | `recordings` | Каталог готового архива |
| `VIDEO_TEMP_DIR` | `temp` | Временные сегменты FFmpeg |
| `VIDEO_INBOX_DIR` | `inbox` | Папка входящих готовых файлов |
| `VIDEO_SEGMENT_SECONDS` | `3600` | Интервал сегментации в секундах |
| `VIDEO_SOURCE` | `none` | `none`, `synthetic`, `ffmpeg` или `inbox` |
| `VIDEO_SOURCE_URL` | — | Адрес RTSP/HTTP-видеопотока для `ffmpeg` |
| `VIDEO_CAMERA_ID` | — | Суффикс имени для отдельной камеры |
| `VIDEO_CAMERAS` | — | JSON-массив RTSP/HTTP-камер для одновременной записи в одном процессе |
| `VIDEO_FFMPEG` | `ffmpeg` | Путь к исполняемому файлу FFmpeg |
| `VIDEO_FFPROBE` | `ffprobe` | Путь к ffprobe |
| `VIDEO_SOURCE_TIMEOUT_SECONDS` | `15` | Таймаут чтения сетевого источника до переподключения |
| `VIDEO_RETRY_SECONDS` | `5` | Пауза перед повторным подключением |
| `VIDEO_INBOX_STABILITY_SECONDS` | `3` | Время неизменности размера файла до импорта |
| `VIDEO_MIN_FREE_BYTES` | `268435456` | Минимальный запас свободного места после сохранения сегмента |
| `VIDEO_LOG_LEVEL` | `INFO` | Уровень журнала |

По умолчанию API доступен только на локальном компьютере. Для доступа из локальной сети задайте `VIDEO_HOST=0.0.0.0`, ограничьте порт правилами брандмауэра и не публикуйте его в интернет: аутентификация в этой версии не предусмотрена.

## Источник видео

### Тестовый источник

Он генерирует видеоряд и звук локально, не подключаясь к камере:

```powershell
$env:VIDEO_SOURCE = "synthetic"
python main.py
```

Режим требует сборку FFmpeg с `libx264` и AAC. Чтобы быстро проверить сегментацию, можно задать короткий интервал, например `$env:VIDEO_SEGMENT_SECONDS = "10"`; для обычного архива оставьте `3600`.

### Поток RTSP или HTTP

Сначала необходимо получить у производителя камеры протокол и точный URL видеопотока, включая путь и, если требуется, способ авторизации. Затем задайте:

```powershell
$env:VIDEO_SOURCE = "ffmpeg"
$env:VIDEO_SOURCE_URL = "rtsp://адрес-камеры/путь-к-потоку"
$env:VIDEO_CAMERA_ID = "camera1"
python main.py
```

Адрес не выводится в журнал приложения. Источник RTSP подключается по TCP; прочие URL передаются FFmpeg напрямую. Поддержка конкретного кодека зависит от камеры и сборки FFmpeg. Тест подключения к реальной камере не выполнялся, поскольку протокол и адрес камеры не предоставлены.

### Несколько камер

Для одной камеры оставьте настройки `VIDEO_SOURCE` и `VIDEO_SOURCE_URL`, как выше. Для нескольких камер укажите массив в `VIDEO_CAMERAS`; у каждой камеры должны быть уникальные `id` и свой адрес `url`. Сервис запускает отдельный FFmpeg-приёмник для каждого потока, а записи публикует в общий каталог `recordings/`. Во временном каталоге для каждой камеры используется отдельная подпапка. Веб-интерфейс группирует записи по `id`; состояние каждого потока доступно в `GET /api/health`.

Пример для PowerShell:

```powershell
$env:VIDEO_CAMERAS = '[{"id":"entrance","url":"rtsp://USER:PASSWORD@192.168.1.20:554/stream1"},{"id":"yard","url":"rtsp://USER:PASSWORD@192.168.1.21:554/stream1"}]'
python main.py
```

Чтобы оставить только одну камеру, удалите из массива лишние элементы или используйте одиночные переменные выше. Не задавайте одновременно `VIDEO_CAMERAS` и `VIDEO_SOURCE`, `VIDEO_SOURCE_URL` или `VIDEO_CAMERA_ID`. Идентификаторы камер разрешают буквы и цифры ASCII, точку, дефис и подчёркивание.

### Передача готовых часовых файлов

Для камер или внешних процессов, создающих готовые MP4, задайте `VIDEO_SOURCE=inbox`. Файл помещается в `inbox/` и должен называться `YYYY-MM-DD_HH-MM-SS.mp4` либо `YYYY-MM-DD_HH-MM-SS__camera-id.mp4`. Сервис ждёт неизменного размера файла заданное число секунд. Чтобы не полагаться на таймер стабильности, отправитель может создать рядом маркер `имя.mp4.ready` после завершения копирования. После успешного импорта исходник и маркер удаляются.

Файл должен быть завершённым MP4. Сервис не переименовывает и не перекодирует его. Неподходящие имена пропускаются и фиксируются в журнале.

## Функции архива

- `get()` в `archive.py` запускает источник (`FfmpegUrlSource`, `SyntheticSource` или `InboxReceiver`) и передаёт завершённые сегменты в архив. Для нового протокола добавьте реализацию в `receiver.py`, не меняя HTTP и хранилище.
- `push()` в `archive.py` публикует готовый сегмент через `VideoStorage.publish_segment()`: сначала копирует его во временный файл в каталоге архива, затем атомарно открывает конечное имя. Существующее имя не перезаписывается.
- `show(name)` проверяет безопасный путь через `VideoStorage.path_for()`; маршрут `GET /api/videos/{name}` передаёт файл блоками и поддерживает один HTTP Range.

Имена потоковых сегментов имеют вид `YYYY-MM-DD_HH-MM-SS[__camera-id].mp4`; время берётся из локальных часов и соответствует началу сегмента. Первый сегмент при запуске посреди часа начинается с запуска до ближайшей границы; далее сегменты привязаны к календарным часам при значении `3600`. Для пользовательских интервалов FFmpeg применяет привязку к локальному времени.

В режиме копирования потока FFmpeg может закрыть сегмент только на подходящем ключевом кадре. Поэтому фактическая граница может немного сместиться относительно календарной; имя файла отражает фактическое время начала. Точность границы зависит от интервала ключевых кадров камеры.

FFmpeg сам закрывает MP4-сегмент перед его атомарной публикацией. Незавершённый текущий сегмент хранится в `temp/` и не появляется в списке API. При штатной остановке процессу FFmpeg отправляется команда завершения, чтобы он мог закрыть текущий сегмент. При аварийном завершении незавершённый файл не публикуется.

В имена с идентификатором камеры добавляется `__camera-id`; используйте уникальный идентификатор для каждой камеры. Если запись с тем же временем уже существует, сервис откажется её перезаписывать и запишет ошибку.

## HTTP API

| Метод и путь | Назначение |
|---|---|
| `GET /` | Веб-интерфейс видеоархива |
| `GET /api/health` | Состояние HTTP и архива |
| `GET /api/videos` | Готовые записи, новые сверху |
| `GET /api/videos/{name}` | Потоковая выдача MP4, включая Range |

Элементы списка содержат `name`, `started_at`, `size_bytes`, `duration_seconds` и `camera_id`. Длительность определяется `ffprobe`, если он установлен и файл читается; иначе возвращается `null`.

Когда задан `VIDEO_CAMERAS`, объект `archive` в ответе `/api/health` также содержит массив `cameras` с `id`, `state` и `last_error` для каждого потока.

```powershell
curl http://127.0.0.1:8765/api/health
curl http://127.0.0.1:8765/api/videos
curl -H "Range: bytes=0-1023" http://127.0.0.1:8765/api/videos/2026-10-15_09-00-00.mp4 --output chunk.bin
```

Маршрут видео выдаёт `video/mp4`, принимает одиночный диапазон байтов и возвращает `206 Partial Content`; некорректные диапазоны дают `416`. Недопустимые имена дают `400`, отсутствующие видео — `404`. Полученный URL можно использовать напрямую в `<video controls src="/api/videos/имя.mp4">`.

## Каталоги

```text
recordings/  завершённые MP4, доступные через API
inbox/       входящие готовые MP4 в режиме VIDEO_SOURCE=inbox
temp/        текущие сегменты FFmpeg и служебный список сегментов
```

## Запуск и остановка

```powershell
python main.py
```

Откройте веб-интерфейс по адресу `http://127.0.0.1:8765/`. Остановка — `Ctrl+C` или сигнал завершения ОС. По умолчанию HTTP-сервер запускается на `127.0.0.1:8765`; если источник `none`, сервер работает, но запись не ведётся.

## Веб-интерфейс

Страница получает состояние через `GET /api/health`, список готовых записей через `GET /api/videos`, а выбранное видео напрямую из `GET /api/videos/{name}`. Она использует только данные API и не содержит демонстрационных записей. Имя файла отображается как текст; список файлов и произвольные пути через веб-страницу недоступны.

Поиск проверяет имя файла, фильтр даты — поле `started_at`; обе операции выполняются в браузере по загруженному списку. Кнопка «Сбросить» очищает фильтры. Выбор «Смотреть» открывает встроенный `<video controls>` с `preload="metadata"`; сервер отдаёт видео потоково и поддерживает Range для перемотки.

Список и доступность API автоматически обновляются каждые 30 секунд без перезагрузки страницы. Интервал задаётся константой `REFRESH_INTERVAL_MS` в `static/app.js` (значение в миллисекундах). Пока страница скрыта, периодические запросы приостанавливаются; после возвращения выполняется обновление. Обновление списка сохраняет введённый поиск, дату и состояние текущего воспроизведения.

Если сервер недоступен, индикатор показывает ошибку проверки API; загрузка списка показывает сообщение и кнопку повтора. Ошибка декодирования видео отображается рядом с плеером. Поддерживаемость кодека зависит от браузера; если камера выдаёт неподдерживаемый формат, потребуется перекодирование на сервере.

## Тесты

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временные каталоги и искусственные байты, не ожидают реального часа и не требуют камеры или FFmpeg. Для проверки визуального тестового потока запустите режим `synthetic` отдельно. Маршрут главной страницы и статические файлы проверяются тестами HTTP-сервера.

## Типовые ошибки и ограничения

- `Не удалось запустить FFmpeg`: проверьте установку, `PATH` или `VIDEO_FFMPEG`.
- Ошибки чтения RTSP/HTTP: проверьте адрес, доступность камеры, порт, учётные данные, кодек и сетевые ограничения.
- Недостаточно места: освободите место или задайте обоснованное значение `VIDEO_MIN_FREE_BYTES`.
- Конфликт имени: существующие записи не заменяются; проверьте часы системы и каталог архива.
- Папка хранения должна поддерживать создание жёстких ссылок внутри каталога архива для атомарной публикации (обычные NTFS и Linux-файловые системы это поддерживают).
- При потере связи FFmpeg перезапускается после паузы. Текущий сегмент, который не успел корректно закрыться, отбрасывается; повторное подключение может вызвать разрыв записи.
- Локальное время при осеннем переводе часов может повторить час. Из-за заданного формата имён такие границы могут конфликтовать; перезапись запрещена.
- Авторизация, удаление видео через API и веб-интерфейс не реализованы.
- Для подключения настоящей камеры нужны её протокол, адрес потока или надёжный способ передачи завершённых файлов, а также совместимый видеокодек.
